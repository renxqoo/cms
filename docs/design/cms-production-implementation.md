# CMS 生产交付施工与验收

状态：已实施，2026-10-27；方案与实现独立审查均已核销，最终整合回归通过。对应[交付基线](cms-production-baseline.md)和[验证矩阵](cms-production-verification.md)。方案独立审查提出的发布视图语义与批量交错问题已纳入基线第 2 节。

## 1. 实施顺序

1. 核实工作区、现有脚本、架构规则与专项设计，明确用户的功能边界及目标环境。
2. 以列表选择、发布状态及逐文档只读退化作为首个完整切片；先记录缺陷测试失败，再实现、针对性验证、四门及独立对抗审查。
3. 完成集合目录、结构、编辑器和媒体装配的一致性，补真实浏览器旅程及桌面/窄屏验收。
4. 对现有全部业务范围执行完整四门，逐项处理真实失败，不调整覆盖率门槛、不跳过失败测试。
5. 对照现有配置补齐可执行的部署与恢复操作手册；在用户选定目标环境后完成入口、提供方、容量、备份及故障演练。
6. 核销已执行证据、未完成项与风险；只有相应验收通过才记录完成，提交后快进合并到 `main` 并 push。生产部署仍需单独授权。

## 2. 测试口径

组件测试通过公开页面及表格行为验证选择范围、历史导航、状态、只读模式和错误路径。状态规则覆盖无发布、当前等于发布、当前不同于发布、直接生效及回收站；published 列表仅显示线上快照，不判断编辑版本。范围切换关闭空闲批量弹窗；在途及未知结果沿用离站保护和任务发现，不混用新范围参数。期望来自明确行为契约。

读取测试验证 update 被拒后 read 成功、read 也被拒、身份失效、服务器错误、取消、快照交错及动作资格不匹配。只读回退不能把可写元数据伪装成只读，不能沿用 update 的字段投影。

真实浏览器复用现有隔离 API/Next/PostgreSQL/SMTP/私有文件装置，覆盖选择范围及发布编辑闭环，分别运行 Bun 开发和 Node 生产模式。权限旅程使用明确角色/文档规则，不以超管旅程代称普通角色验证。

需要断言浏览器响应正文的测试通过 `captureApiJson` 在浏览器接收回执前读取实际 BFF 响应，再原样交付该响应，校验浏览器实际状态码及已捕获 JSON；带筛选的请求对路由与观察使用同一 query 匹配。请求只执行一次，不改正文、状态或应用导航逻辑，不依赖后续导航仍可读取浏览器网络缓冲区。旧 `waitForApiJson` 及所有调用方同步迁移，不保留双观察路径；独立 APIResponse 的读取保持原契约。复制与清理旅程的正文丢失失败证据分别保留于 `/tmp/cms-production-response-capture-before.log`、`/tmp/cms-production-cleanup-capture-before.log`。

账户依赖回归保留角色变更、撤销和邀请的原断言，保存后详情会异步刷新，重邀按钮依赖读取就绪。回归通过异步可访问角色查询等待刷新后的邀请按钮，不把成功提示出现等同于整个界面已就绪；日志不能单独证明弹窗退出是唯一原因。原失败证据为 `/tmp/cms-production-dialog-transition-before.log`，对应文件修后 19 项通过；没有增加超时、重试或跳过。

富文本列表取消后的活动状态也等待明确的段落按钮就绪，而非仅以列表按钮未按下推断段落状态已同步；原数据、列表移除及段落活动断言全部保留。修前证据为 `/tmp/cms-production-toolbar-transition-before.log`，修后该文件 4 项通过。没有改变编辑器实现或降低断言要求。

## 3. 工程门禁

`bun run lint`、`bun run typecheck`、`bun run build`、`bun run test` 全部通过后才提交。完整测试报告独立用例数、API/浏览器旅程数及全仓 statements/branches/functions/lines，并分别核对 vitest 配置中的全局和分组门槛。独立审查者只审方案/diff/测试口径，不参与实现。

## 4. 结果

本批完整四门通过。259 个文件、2332 项单元及集成测试全部通过；真实 API 跨进程旅程 8 项，开发与生产浏览器旅程 114 项全部通过。完整测试在退出即删除的独立临时 PostgreSQL 数据库中执行，未修改业务数据库。lint 零错误零警告，后端、共享 UI、Next 类型检查及 API/Next 生产构建通过。

全仓 Istanbul 实际覆盖率为 statements 93.90%（16378/17441）、branches 89.21%（12356/13849）、functions 96.18%（4922/5117）、lines 96.57%（14506/15021）。vitest.config.ts 的全局、admin、UI 和 oxlint 分组原有门槛全部通过，阈值未调整。

修前失败证据：`/tmp/cms-production-behavior-before.log` 的 6 个公开组件用例全部失败；`/tmp/cms-production-default-locale-before.log` 的默认语言回归失败。修后相关页面、读取和状态矩阵均通过。完整测试首次运行的新配置用例错误地使用装置不支持的语言键，已改为装置既有 `zh` 并保留原默认语言及顺序断言，单独 4 项与随后完整四门通过。

本批日志为 `/tmp/cms-production-{lint,typecheck,build,test}.log`，覆盖率摘要为 `/tmp/cms-production-coverage-summary.json`。新增真实内容旅程为 `e2e/admin-content-workflow.browser.spec.ts`，开发/生产两模式均验证发布快照、私有草稿状态、清选择、浏览器返回和 390px 结构页无溢出；已查看生产窄屏截图。

独立实现审查发现的嵌套字段语言规则误述已修复；修前 `/tmp/cms-production-nested-locale-before.log` 记录该公开页面回归失败，修后同文件 13 项通过。响应捕获及异步界面状态的测试修正也已通过独立复审，没有增加重试、跳过或弱化断言。主分支已有的集合侧栏导航保留，整合后重新完成上述全部门禁。
