# 管理界面真实浏览器验收

状态：方案定稿，2026-10-26；配套访问管理实施契约，属于既有应用联调计划的测试装置与旅程扩展。

## 装置与边界

每个被选择的browser spec文件依次使用独立的Bun API/Next dev及Node API/Next prod世界；入口先构建API与Next一次，不跨文件共享身份、邮箱、数据库、存储或限流记录。每组 finally 关闭全部资源；SIGINT/SIGTERM打断当前Playwright子进程后仍清理已启动世界，失败同样清理。保留真实email/IP/操作限流，不重置限流表、不等待窗口、不增加自动重试。

资源自动创建与文件替换分别使用 `admin-assets.browser.spec.ts` 和 `admin-asset-replacement.browser.spec.ts`。完整集合权限目录需要多页读取，两个独立旅程不共用一分钟的 HTTP 准入窗口；各自保留实际上传、修订替换、当前文件下载和历史字节核对。默认入口和装置回归确认两份文件均被执行且每份只有一个旅程。

每个文件的trace、截图等产物保存到独立的test-results子目录，后续文件不会覆盖前一文件的验收证据。待激活管理员装置先通过真实创建接口和SMTP建立未消费的邀请，再于Next启动前把该隔离数据库中的邀请创建时间设为两分钟前，满足真实重邀冷却前置条件；不调整服务端策略、计数或token消费状态。

现有认证文件的正常登录预算已占满同一邮箱五次/分钟。新增管理旅程不得靠共用该世界串接更多登录；按文件隔离。账户和被验动作通过真实HTTP执行；内容旅程的集合权限绑定与导航在启动Next前通过同一正式业务API装配到隔离数据库，不经过HTTP准入，不修改限流策略或计数。默认test入口由主会话统一修改。

内容世界还在隔离数据库预置一条pending、blocked且保留期未结束的清理账本，作为管理重试的明确前置状态。浏览器验证其202受理、阻塞解除与保留期仍生效，不将该前置状态当作真实提供方故障证据；提供方故障与恢复仍由资产后端真实存储装置覆盖。

Playwright通过同一Bun测试进程的loopback只读邮箱桥读取隔离SMTP的实际消息，使用每组随机capability及测试专用配置。桥不注册在产品API、不把Bearer或消息交给浏览器页面、不发送外部邮件；完整URL须直接提取自SMTP并校验所属前端origin和对应动作。消息数组按索引读取，关闭桥及测试SMTP后不保留消息。错误请求、未知路径和无capability均拒绝，响应no-store，连接在清理时回收。关闭回归先等待真实HTTP响应，确认服务端已接管连接，再暂停读取并关闭；客户端TCP connect事件不能代替服务端接收确认。服务端关闭后恢复客户端读取EOF，保留客户端关闭与连接释放断言。

测试默认没有console/pageerror白名单。预期HTTP错误仅按明确method、URL、status和次数登记，不吞应用错误。纯跨进程设置及冲突注入可使用真实HTTP；被验动作通过UI执行并断言终态。过程不修改生产限流、覆盖率、超时门槛或无效返回。

## 旅程与先行测试

账户旅程包含真实邀请邮件激活、重复使用拒绝、登录、资料更新与CAS冲突保留草稿、未保存资料时改密、旧会话/旧密码撤销、新密码登录、找回邮件和一次性重置。beforeunload在成功改密后的安全跳转不应拦住导航；遇到原生dialog记录并接受以继续取证，但断言其不该出现。

管理员旅程包含创建邀请、投递状态与重邀、目标角色/状态改变的会话及旧token撤销、自身保护和读取依赖。RBAC旅程包含角色两保存区、disabled已有授权、权限引用冲突、普通管理员无security写、可信导航树、真实端点绑定与审计详情。独立恢复入口通过实际安全读取和原CAS写入验证，普通目录解绑后可重新绑定并恢复读取。

装置先验证spec分组保留所有CLI筛选、每组独立并串行、部分启动/Playwright失败仍清理、信号打断清理；邮箱桥验证授权、消息快照、无效输入、no-store和close。新浏览器旅程先单文件开发/生产运行，再与已有文件组合运行；任何产品缺陷先保留失败证据并交实现方修复。
