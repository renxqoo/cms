# Collections 反向关联

Join 字段由配置的目标集合及反向关系路径读取，不持久化到正文。配置支持一个或多个目标集合、固定 where、defaultPageSize、defaultSort 和 orderable。目标关系须引用源集合；排序流只允许单一目标。未配置页大小时使用部署的默认分页策略，页大小与展开深度服从现有资源限额。

documents.join 通过源文档和稳定字段 ID 读取分页；普通文档读取通过 joins=false 或按字段路径的查询对象关闭或选择各 Join。返回值统一为包含 rows、page、pageSize、hasNextPage 的对象，只有 count=true 才包含精确 total。没有数组旧返回或第二套 Join 路径。请求筛选、固定筛选、反向关联条件、目标集合权限及字段策略均在 SQL 分页之前处理；多个目标使用 SQL UNION 后统一排序、分页，禁止先按集合分页再在 JavaScript 筛选或拼接。count=false 只读取额外一行判断下一页。

near 条件保留参考产品的平面几何距离排序；此时 sort 返回空数组，管理端不提供按该结果重排自定义顺序。普通字段排序和固定默认排序只公开当前目标共同许可的路径。

读取先确认源文档与 Join 字段可读，再对各目标复核当前权限。正文投影继续使用变换前的权限数据，遵循 defaultPopulate 与各字段 maxDepth；筛选、排序、total 和目标标签不得扩大可查询或可读字段。新建文档没有已保存的反向引用；管理端在保存后展示关联列表。列表支持独立查询、分页、打开关联文档以及配置允许的顺序调整。

每个可排序 Join 使用源集合稳定 ID 与 Join 字段稳定 ID 组成独立排序流；同一 Join 在不同父文档中的排序属性共享，与参考产品为每个 Join 注入一个目标排序字段的行为一致。集合自身顺序和各 Join 顺序分开。0013 前后的查询预设不承载排序键，客户端只使用不可推断位置的 UUID 令牌。

0023_join_order_scopes.sql 为现有顺序表增加 scope_key，并保留集合基础流。基础流具有不可变 initial_position；尚未移动的 Join 文档使用该位置，已移动文档使用所属 Join 流的精确 numeric 位置。首次重排只物化被移动文档，不为每个新配置在请求中全量回填。读取没有写入。令牌结合基础流与 Join 流版本，新增和物理删除借既有基础触发器使旧令牌失效；归档、恢复与配置重新启用保留既有位置。重排使用服务器读取的相邻位置和原有有界 dyadic 算法，事务内验证令牌、源与目标可见性、移动权限和成员资格。共享基础流锁串行化重排及新增，预留位置确保新文档仍追加在所有既有顺序之后。

迁移窗口先停止旧 writer、维护与 CLI，备份并执行追加迁移，再统一切换 API、管理端和生成产物，核验触发器、复合主键、运行权限与 readiness 后恢复写入。新配置的 where、页大小、排序和读返回不改变旧核心 collection/field 数据指纹；目标或反向路径改变仍走现有显式配置演进。观察版本冲突、权限失败、分页预算与缺失基础排序记录。不存在运行时旧摘要兼容或基础流双写。回滚先停止新 writer，恢复统一旧产物须先以审查后的逆向迁移保留基础流并导出 Join 顺序；不能直接启动不认识复合排序键的旧产物。单纯关闭 Join 的 orderable 配置不删除顺序数据。
