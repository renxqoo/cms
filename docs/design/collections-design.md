identity/access/audit/platform、内容表、内容 API、持久化内容任务及资产后端均已实施。采用三工作区、Hono、PostgreSQL/Drizzle、Bun 1.4.4 开发和 Node 生产。保留既有授权锁、权限即时生效、审计原子性、严格输入、幂等及错误契约。前端属于后续阶段。用户裁决（2026-10-26）：本轮同时完整实施物理资源上传、图片处理、私有下载与恢复，允许多子 agent 以独立 worktree 并行。未支持的配置必须明确拒绝，不能接受后忽略。

## 2. 单一配置源与稳定身份

集合使用稳定 id、API key、schemaVersion、label、fields、indexes、search、defaultSort、mode、history、singleton、locales、access 和 extensions。字段使用稳定 id、name、type、约束、默认值、本地化及读写/查询策略。稳定集合/字段身份在 API 重命名后保留；物理名称同时包含 schemaVersion 的命名空间，各版本投影独立，旧表不因重命名或回填被覆盖。保留旧 schema 解码定义直至所有历史修订及部署兼容窗口释放。

配置严格运行时校验，拒绝未知选项、重复身份/路径、保留名、非法关系/反向 join、无效索引/搜索字段及不适用版本组合。先归一化，再冻结实例注册表；函数必须具有显式 version。配置行为摘要与物理映射摘要分开。生成不读取环境、不连接服务、不依赖已有生成物。

基础字段包括 text、textarea、number、boolean、date、email、select、code、json、point；组合包括 group、array、blocks、命名 tabs；展示布局不生成数据。富文本为 version=1 的结构化树，节点注册有版本；拒绝任意 HTML/危险链接。relationship 支持单/多目标及顺序，join 为只读反向关系。locale 显式选择，写入不回退，读取仅按明确 fallback 顺序回退。

## 3. 物理计划与迁移

共享 content_documents / content_revisions 仅保存身份、指针、schema、状态及时间，不保存通用 data。配置生成集合级类型化修订表、当前及发布活跃视图唯一性保留和组合子表；JSONB 仅用于 JSON/富文本/坐标等明确字段形状。数组子项有稳定 UUID、位置、父项和 block 类型；关系具有来源修订、字段路径、目标集合/文档和顺序，真实 FK 保护归属。唯一约束覆盖 current 与 published 两个活跃视图的值并集；同文档相同键去重，其他文档不可占用任一视图的键。回收站仍保留 current 键，purge 才释放，避免恢复时无声覆盖。历史非活跃修订不占用唯一键。每个修订属于同一集合/文档；指针用复合 FK 约束。

database 的 schema-plan 仅描述列、键、索引、约束；codegen 生成确定性 SQL 与 Drizzle。content/adapters/postgres 编译语义到物理计划；应用命令装配、写生成物并核对漂移。迁移只有一条有序链，API 启动及请求不执行 DDL。ready 校验已应用 schema/映射范围；滚动兼容窗口由部署显式列出，不能用单一最新行为摘要阻断兼容旧实例。

当前无业务数据，首批为新增表。后续破坏性变更先生成显式演进报告，要求转换、回填、历史解码及回滚计划；不得自动把不同身份字段猜作重命名或执行破坏性 DDL。兼容窗口、可观测校验和删除条件随每次演进计划提交；没有双轨业务引擎。

## 4. 查询、授权与资源预算

请求 AST 支持 and/or、eq/ne/in/notIn/exists/gt/gte/lt/lte/contains、嵌套路径、关系、q、多 sort、page/pageSize、select、depth、locale/fallback 和 mode。按类型验证操作符、字段可查询权限，再编译参数化 SQL；列表/总数共用授权谓词和读模式。标识符只来自编译映射，无内存全表筛选。published 查询始终选发布修订，editing 选当前修订。

多态关系的嵌套字段路径可只存在于部分目标集合；缺少完整路径的目标分支不匹配，所有目标均无该路径才返回 invalid_input。具备路径且可读的目标分支仍完整校验字段查询权限及类型，不通过跳过查询禁止或类型错误的可访问分支掩盖错误。目标 scope 明确拒绝读取时，该分支保持不匹配，不改为字段查询错误；全部目标的路径结构仍必须合法存在于至少一支。同名 blocks 子字段覆盖所有合法 block 分支；exists:false/ne/notIn 按全部分支的否定语义处理，任一可探测分支禁止查询时整条路径拒绝。每一跳以当前来源 locale 解析目标 locale/fallback 和策略，不能用根 locale 的一次预计算替代。

关系路径的负向筛选要求至少一条可读且完整的目标链；空引用、只有缺路径目标或不可读目标时不命中。完整目标链存在但最终叶字段缺值时可命中负向条件；中间关系为空属于无完整链。直接字段沿用缺值语义。相同 API 路径同时由 group 和关系到达时合并全部合法分支，正向命中聚合后只否定一次，不能分别否定各 block 再 OR。循环/多态路径的结构预检及实际 SQL 展开都受配置中的节点/深度预算约束，目标策略编译也计入同一展开预算。

RBAC 使用真实 operationId + collection scope，默认无绑定拒绝。集合策略返回 allow/deny/类型化 where；字段 read/write/query 分别检查。策略在业务内且安全锁后执行，超管也不能绕过完整性。投影、关系目标、版本比较及任务结果再次按当前权限过滤。依赖文档值的字段策略不具 SQL 表达式时禁止查询探测。

配置层注入预算：正文 1 MiB、页上限 100、AST 节点 100/深度 8、字段深度 8、数组/blocks 每字段 1000 项、展开深度 3/节点 500、结果 2 MiB、单请求 SQL 200、同步批量 20/总受理 1000、任务领取 20、租约 30 秒、重试 3。沿用请求 15 秒、SQL 5 秒、锁 2 秒和有限连接池。任何预算触发显式失败，事务回滚；不截断为假成功。查询不新增进程定时器；维护复用现有单一有界循环。

## 5. 文档与版本契约

路径沿用 modules-and-contracts.md §4。创建、复制、自动保存、发布、恢复及任务受理要求 Idempotency-Key；更新及状态转换带 revision（正整数），过期返回 version_conflict。DTO 为 {id,collection,revision,versionId,publishedVersionId,trashedAt,createdAt,updatedAt,data}；服务端元数据禁止客户端写入。时间 UTC ISO，ID UUID；未知字段严格拒绝。

直接生效无历史、直接生效保留历史、草稿/发布保留历史三种模式。保存创建不可变修订；draft 可缺 required，但所有已填值类型、唯一及引用仍校验。publish 完整校验确定的当前修订，独立授权；unpublish 仅清空发布指针。autosave 幂等新草稿。历史恢复按当前 schema 显式解码/转换后新建修订；直接生效还要求生效写权。复制重校验唯一值及关系，不继承发布状态。

回收站取消发布；重复归档无新副作用，恢复回收站不等于恢复历史。purge 要独立权限、保留期限及外部历史引用检查；自身历史不算外部。关系删除默认 restrict；解除创建来源新修订，cascade 仅逻辑归档并逐项授权，不隐式删除历史。资源锁全局排序，竞争引用建立与清除。

历史读取独立授权、版本必须属于目标文档，diff 只比较可读字段。裁剪保护当前、发布、待执行计划以及配置保留数量/时间窗口；无历史模式及时移除无用修订。审计不记录正文/字段值；审计或幂等失败整体回滚。幂等仅存结果资源/修订引用及脱敏状态；返回正文的重放重新执行当前文档谓词和字段/媒体授权，再动态投影当前资源，不能返回旧缓存 DTO，也不承诺重放字节相同。purge/批量受理/计划只返回不含正文和目标详情的结果身份回执；重放先重新校验当前操作/集合权限，资源正文及任务详情仍必须另经当前完整授权读取，jobId 或 purged 回执不授予访问权。指纹包括 collection、路径 documentId、mode 和完整规范化输入。

## 6. 持久化工作与一致性

安全锁 → 部署统一的 content 变更 fence advisory 锁 → 幂等 → 业务行锁 → 写入/审计。当前 fence key 由应用配置注入为 1171904223；content/asset 所有变更和消费者在任何 job/upload/content 行锁前获得它，网络工作仍在事务外。该单一短事务写 fence 避免任务领取/内容消费/上传状态的锁顺序反转，普通内容读和下载不取此写 fence。它会限制并发写吞吐，当前没有压测数字，不宣称已经验证容量目标；保持 2 秒锁超时和 5 秒 SQL 期限，只有测出瓶颈后才按资源拆分协议。事务只做 SQL/受限同步规则，不调用网络。任务受理与业务同事务，持久化 actorId、collection、目标、revision、执行时间和逐项结果。jobId 不授予访问权；查询按当前原动作/范围及资源读权投影。

定时发布绑定确定修订，执行时重新检查账户/角色/绑定/集合策略、预期 revision、归档及发布完整性。撤权为失败终态。领取通过 FOR UPDATE SKIP LOCKED，owner+generation+lease；每个逐项事务先锁任务/条目并核验 owner+generation+lease，再执行重新授权、revision CAS、业务写、审计和逐项结果；提交时仍持同一任务行锁。过期代次不得产生业务副作用，仅终态 CAS 不足以保护。终态 CAS 拒绝过期消费者。事务内纯 SQL 批量可单项事务，逐项真实成功/失败；无外部效果，不承诺网络 exactly-once。进程退出停止领取并有界等待；到期工作由另一实例重领。

扩展为受信任的版本化校验/转换及持久化提交后意图。扩展不持有结束事务权限，不能取消授权、校验及审计；异步效果由具名处理器消费持久化意图，不以未等待 Promise 实现。

## 8. 资源子系统契约

content 的上传型集合客户端仅提交 uploadId，内部解析后绑定不可变清单，客户端不能提交裸 manifestId；upload 字段是关系到上传型集合并固定其清单，富文本媒体也固定清单。assets 不读取 content 私有表。assets 的事务参与能力消费 ready 会话、pin/release 来源修订清单引用、读取可用清单、登记清理；全部显式接收调用者 tx，不能结束事务。来源修订/字段/媒体文档/manifest 的绑定用于历史文件读取；HTTP 先经 content 的来源和目标权限，再交 assets 传字节。

上传会话按主体、集合、用途、目标文档/revision、期限登记。上传和图片在 SQL 事务外执行；完成绑定以短事务重新授权并核验清单。会话消费严格匹配 actor、collection、create/replace 用途及替换 document/revision；历史/复制清单复用只能由已授权媒体确定修订或来源绑定解析，裸 manifestId 不授予引用权。上传身份是 UUID，字节流单会话一个文件，先验证长度/实际 magic MIME/摘要，再提交不可变对象。替换、裁剪/焦点和 reprocess 均生成新 manifest，永不覆盖旧对象键。只允许配置批准的 PNG/JPEG/WebP/GIF 及附件 PDF；HTML/SVG/可执行文件拒绝。实际类型与声明类型不一致拒绝。

配置注入会话 20 MiB、批量 100、上传并发 4、队列 8、图片像素 40M/帧 1、处理超时 15 秒、输出 20 MiB、原件和衍生对象保留至少 PITR 7 天、会话 30 分钟。sharp 提供解码/旋转/裁剪/焦点/resize，处理配方和处理器版本纳入指纹；预算与支持格式必须由真实字节测试。存储按下面的显式选择和自动回退规则装配；本地键严格固定模式，防路径/符号链接，私有文件无静态路由。

用户裁决（2026-10-26）：没有 S3 配置时使用本地存储，包括 production 环境。未显式选择 driver 时，无 S3 bucket/region/endpoint 使用本地，提供 S3 身份配置时选择 S3；显式 driver 优先，部分或非法 S3 配置明确拒绝。空 S3 环境值视为未设置。本地键、目录私有权限和生命周期规则保持一致；多实例若使用本地驱动必须指向同一持久化共享卷，不能各自保管独立副本。

对象有独立身份/摘要/键/状态及清单引用；一个原件可以被多个清单共享。清理竞争清单锁再排序对象锁，确认无引用/pin且超过保留窗口后登记 deleting。对象键永不复用，重复删除幂等。上传取消/到期保留上传代次、暂存前缀、在途写入责任；不以删除一次或 URL 过期当作最终回收。默认 API 代理流式上传，不签直传 URL、不启用分片；适配器能力元数据明确只支持代理上传，避免遗留不可撤销写凭据。客户端断流中止流/处理、释放容量，扫描账本回收候选对象。

content 拥有文件夹/移动/目录防环、非空删除和媒体引用查询。资源路径沿用 modules-and-contracts.md §5，操作/输入 schema 单源注册。下载支持 Content-Disposition 安全文件名、实际 Content-Type、Content-Length、ETag 和私有 no-store；鉴权后返回可取消有界流，不暴露对象键/存储凭据。处理/重新处理通过持久化任务，状态 queued/running/succeeded/failed/cancelled 和代次 CAS；批量逐项结果可查询。

部署不在本次授权中；S3 驱动使用本地可编程兼容装置验证接缝，真实账号 opt-in。共享生产桶生命周期/PITR/多故障域仍须部署阶段配置及演练，本地门禁不能证明基础设施 SLA。


## 9. 后台身份参与能力

access/composition 的 authorizeActor(tx,{actorId,operationId,scope}) 仅供可信任务装配。它从 writer 重新读取账户，要求 active/activated，再复用普通请求相同的角色、操作绑定、范围和权限判断；拒绝 public/authenticated 操作，不能把任意管理员身份当作后台登录接口。调用者持安全共享锁，任务租约/代次、业务及审计仍在同事务。注销会话不撤销已受理任务，账户禁用、角色禁用或撤权则阻止后续任务执行。HTTP 不导入该能力，也不接收 actorId 作为主体。


## 10. 后续 schema 演进与发布完整性

生成物保存 ContentSchemaSnapshot（物理计划及集合稳定身份/API key/schemaVersion），而非把全量 CREATE 当作后续迁移。每个生成 SQL 迁移附带 .plan.json 审查快照（previous/next）；重复生成使用该快照，禁止覆盖已提交迁移。未指定新迁移时只能更新不改变物理或 schema 注册要求的行为/类型产物；结构变化须显式生成增量并审查。破坏性变化输出人工迁移原因，不能生成假成功。生成入口不读取环境/连接服务。

集合 API key 变更涉及权限范围、接口绑定和已受理任务，不自动把旧 scope 当作新 scope；演进报告明确要求人工迁移。需要人工步骤的计划，生成命令只在显式提供 --reviewed-sql 文件后保存安全增量及附加 SQL，审查文本与 previous/next 一起不可变写入 sidecar；断电重试可从该记录恢复。该入口仅生成文件，不执行 SQL、不认证人工 SQL 的业务正确性，也不绕过数据库 schema 身份/就绪/激活约束。审查必须排空或明确迁移旧任务及绑定；迁移和验证后才切换 API，不留下旧 key 别名。

显式类型/locale 转换保留旧解码模型，回填按有界页和持久化每修订目标标记执行，不以 UUID 高水位假装排空旧 writer。准备态新 schema 不能 ready；旧 writer 停写、最后回填及 activate 核对排空后，新 writer 才生效。任意 JavaScript 转换不承诺滚动双写。回滚保留旧结构；一旦有新 schema 写入，应使用已审查的逆向转换或前向修复，不能直接以旧程序读取不认识的新修订。部署停写/入口切换由实际发布流程负责，本次只交付受控命令和验证。

同类型转换也可能改变实际值，因此字段表、复合索引投影和唯一保留按 schemaVersion 隔离；回填只写目标版本投影，来源原始修订保持不变。旧表精确保留，迁移仅增加所需目标投影，不把共享字段表的冲突忽略当作回填成功。字段/locale/复合索引等会影响数据或投影语义的变化必须提高 schemaVersion，保留旧解码并完成回填；纯保留期限、显示标签等行为配置不触发数据版本迁移。

回填标记同时覆盖修订和文档 revision。已生成目标投影的草稿仍可能被旧 writer 发布；尾回填必须按最新 current/published 指针重新验证目标 schema 的完整性，不能因修订标记已存在而跳过生效校验。失败保持准备态，激活及成功审计均不得提交。

schema 转换不凭 JSON 引用创建文件能力。目标投影的每个 upload/富文本媒体引用必须能按稳定字段、子项路径及 localeMap 映回原修订的同媒体身份引用；字段重命名和语言映射保留原固定清单。新增媒体身份、替换身份或无法映射的引用位置在回填中返回 invalid_input，整页回滚并保持准备态；普通文档关系仍可显式转换。新增媒体字段先以可选 schema 上线，经现有受授权文档写入绑定清单，填充后再按需要提高 required 约束；不在离线回填中绕过资产授权或伪造 manifest。

发布状态是文档级而非按语言独立。direct 生效和 drafts 发布都对全部配置 locale 的有效读取值执行完整校验，使用明确 fallback；原始各 locale 仍独立存储，不把回退值写成翻译。需要允许未完成翻译的部署可为相应语言显式配置 fallback；无回退且缺少 required 值时不能发布/直接生效。复制和历史恢复保持相同规则。

创建、更新、自动保存和复制覆盖值支持互斥的两种写入粒度：locale/data，或非空 dataByLocale；不能混传。后者在一个事务内提交多个已注册 locale，逐语言校验写权及类型。所有语言共享的非 localized 字段、数组顺序、blockType 和 child ID 是单一事实，显式冲突拒绝；缺省值和新 ID 的规范化不能取决于对象键遍历顺序。

PATCH 对 group 递归合并；数组及 blocks 的顺序显式替换，同 stable child ID 的内容递归合并。省略子字段保留原值，显式 null 或删除旧 row 才表示删除；删除必须检查旧值中受保护的后代。显式提交 write:false 字段始终拒绝，即使与原值相等，不通过相等结果泄露不可读字段。单语言与多语言共用同一规范化引擎；只有明确替换/删除容器才改变共享结构。

## 11. 富文本受信任节点

字段可注册版本化节点 type 及同步 validator/引用提取器。节点严格为 type/version/payload；不允许覆盖内建节点或重复注册，注册器和函数版本纳入行为摘要。payload 必须为有界 JSON，validator 明确返回 true 才接受；Promise、异常形状、未知版本和未知键失败。引用提取结果校验已声明目标集合、UUID、media 与稳定路径，并进入相同目标授权和历史固定清单流程。后端不执行或生成 HTML；安全字段元数据只暴露节点身份/版本，不公开函数。
