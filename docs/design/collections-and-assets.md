状态：后端设计基线，2026-10-26；完整后端已实施并核销。本文定义能力范围与存储原则；当前 DTO、字段精度、容量预算及发布协议见 [实施设计](collections-design.md)，实际验证结果见 [验收记录](collections-verification.md)。

## 2. 完整交付能力

| 能力 | 目标行为与验收 |
| --- | --- |
| 集合定义 | TypeScript 定义集合身份、字段、标签、默认排序、索引、访问策略、上传及版本模式；错误配置在构建或就绪前失败 |
| 单例内容 | 配置为单例的集合用于站点设置等内容；复用相同字段、查询、权限和版本规则，不再建立第二套内容引擎 |

| 本地化 | 字段级 locale 值、默认 locale、回退顺序、缺失值及唯一性规则；查询和读写显式指定 locale，不混写不同语言 |
| 查询 | and/or、类型适用的比较与集合运算、嵌套路径、关系条件、搜索、多字段排序、分页、字段投影和有界展开；由统一查询编译执行 |

| 上传型集合 | 媒体也是集合文档，可增加替代文本、版权、分类等任意受支持字段，复用查询、权限、版本和回收站 |
| 资源工作流 | 上传、验证、处理状态、替换、目录/移动、搜索、批量受理、引用查询和受控下载；替换不能破坏仍被使用的历史字节 |
| 图片处理 | 原图、尺寸与方向、缩略图/变体、裁剪和焦点、重新处理；配置、输入及处理器版本形成可追踪的派生结果 |

## 3. 一个定义源，多种明确产物

```text
应用的 TypeScript 集合与字段定义
  → content 校验、归一化、稳定身份解析
  → 只读运行时注册表
      → 草稿/发布校验、字段读写策略及引用提取
      → 查询能力与安全字段元数据
      → TypeScript 内容类型和 HTTP/OpenAPI 数据 schema
      → content 的 PostgreSQL 映射编译器
          → 物理存储计划、查询映射与 schema 指纹
          → database 的 schema 生成能力
              → 已提交的 Drizzle schema 和迁移审查输入
```

content 拥有集合/字段语义；content/adapters/postgres 拥有其 SQL 映射。database 只接受明确的物理计划，负责生成 schema、连接与唯一迁移链，不导入 CMS 或应用配置。生成命令装配两者；不能让 database 的 schema 文件反向执行集合配置。

生成入口只加载定义、归一化和编译能力，不加载依赖生成表的运行时查询/装配。全新检出且尚无生成物时能够生成；生成模式不要求连接生产数据库、对象存储或 SMTP。

运行时注册表和已生成的映射是不同产物，不在每次请求重新编译。部署分别核对行为配置版本、物理映射指纹和已应用迁移的兼容范围，失败不进入 ready；滚动窗口允许明确兼容的新旧映射，不要求所有存活实例持有同一个最新配置摘要。控制行为的函数须显式声明实现版本；不能靠函数 toString 或仅对 JSON.stringify(config) 取摘要假装检查完整。

内容类型、数据库行、HTTP DTO 各有边界；同一字段定义驱动映射，不直接公开 Drizzle 行。安全元数据不包含服务端函数、内部表名、存储密钥或无权读取的字段。

扩展点采用受信任代码注册：输入归一化/校验、受限事务内规则、提交后持久化工作意图。权限、字段验证、事务结束权和审计不能被 hook 关闭；事务内 hook 不等待网络，提交后网络效果进入持久化任务。这里需要的是可测试的扩展能力，不允许运行管理员提交的任意脚本。

## 4. PostgreSQL 建模及迁移

采用配置编译产生集合级关系模型。共享资源身份及修订目录提供跨集合寻址；集合字段落在所属集合的类型化表、修订表及必要子表。共享目录不承载全部业务 data。

| 数据形状 | 存储方向 |
| --- | --- |
| 标量与 group | 类型化列及稳定字段映射；空值、默认值和约束由字段语义决定 |
| array / blocks | 有父修订身份、稳定子项身份、顺序和 block 判别的子表；不丢失顺序或多级嵌套 |
| 单个/多个关系 | 具有源修订/字段/顺序和目标集合身份的关系记录；目标存在性及类型有约束 |
| localized | 所属修订和 locale 下的值/子记录，唯一性按配置范围执行 |
| JSON / 富文本 | 适合树结构的 JSONB，仍执行节点/大小/引用校验；可搜索内容有明确索引映射 |
| 图片与上传字段 | 保存媒体文档身份，并登记版本固定的文件清单绑定；存储键不由用户填写 |

JSONB 是特定字段的存储选择，不作为放弃类型化查询、关系和索引能力的理由。共享身份目录与集合数据同步写入；历史修订具有集合、父文档和 schema 身份，不能把另一个文档的修订设为当前指针。

集合及字段都有稳定内部身份，展示名、API 字段名与物理映射分开。重命名须显式识别，禁止猜测“删列 + 新列”后丢弃数据。历史修订的字段映射/解码器在仍有保留版本时保持可用；删除字段、类型转换和 locale 变化提供可审查的数据迁移，并验证恢复行为。

索引与唯一性须区分当前有效内容和历史修订；旧版本同值不能错误阻止当前文档保存。草稿缺少必填值与发布完整校验分开，但类型和现有值的唯一性不因草稿跳过。复合唯一、locale、归档记录以及并发写的语义在字段契约中显式规定，并以数据库竞争测试验证。

配置生成先产生确定性 schema/映射，再生成并审查迁移。破坏性变化、回填、历史版本转换和大索引创建必须显式编排；不依靠自动 diff 证明数据安全。API 请求和 API 实例启动不执行 DDL。开发同样使用有序迁移链，不靠隐含 push 与生产形成两套结构。

目前没有存量业务数据，按此模型开始实现。将来 schema 演进沿用扩展、验证、切换、排空和删除的部署协议；不能同时保留两套目标内容引擎。

## 5. 查询与权限共同编译

先解析有界查询 AST，再结合操作、collection scope、字段权限及 locale 生成参数化 SQL。字段路径和关系目标只来自规范化注册表；未知字段、类型不适用的操作符和超出预算的展开明确失败，不执行客户端提供的 SQL/任意表达式。

可进入 SQL 的授权结果采用允许、拒绝或受限的类型化查询谓词；不声称能将任意 JavaScript 访问函数自动翻译为 SQL。依赖文档值的字段展示规则与可查询规则分开定义；没有安全查询表达的字段不允许通过过滤/排序探测，完整读值仍执行字段策略。

支持的集合字段应具有声明清楚的查询能力。不能把缺少 SQL 实现隐藏成内存过滤、无声忽略或只搜索几个固定投影。虚拟字段/反向 join 的筛选排序需要明确的查询表达能力；不具备表达式的虚拟值只能投影，并在元数据中说明。

rows、total 和分页使用同一权限谓词。过滤、排序、搜索本身也可能泄漏敏感字段，必须先校验其可查询权限；只在返回时隐藏字段不够。关系目标授权在 SQL 查询与展开时共同执行；深度、节点数、返回字节、SQL 数量和时间都有预算，批量加载避免逐行 N+1。

对同一资源，编辑草稿、读取发布内容、查看历史分别使用明确读模式。发布列表从已发布修订查询对应字段，不能拿最新草稿的标题/排序/总数冒充已发布视图。管理 API 仍需认证，匿名内容交付另有授权边界。

## 6. 媒体文档与物理资产的边界

content 拥有上传型集合文档、自定义字段、编辑/发布/历史语义、文件夹归属和文件操作编排。assets 拥有上传会话、不可变文件清单、原件/派生对象、引用记录、处理状态和存储恢复。content → assets，assets 不反向依赖 content。

文件清单记录原件和各派生对象的身份、校验摘要、实际类型、尺寸、处理配方及版本。一个媒体文档可以先后引用多份清单；替换文件或改变裁剪/焦点产生新清单，不覆盖旧对象键。文档版本、发布快照以及引用该媒体的保留内容版本都固定所需清单，不能只保存会变化的 mediaId。

引用图分为“内容修订 → 文件清单 → 物理对象”，处理中工作对对象另有持久化 pin。清单可以共享原件或派生对象，物理对象有独立身份、唯一键/对象版本、状态和 manifest→object 关系；清单引用归零不代表对象引用归零。登记/释放清单引用竞争清单行锁；增加/移除对象关系、工作 pin 与对象 GC 竞争同一对象行 FOR UPDATE 锁。取锁顺序为安全锁、幂等竞争、排序的内容资源锁、排序的清单锁、排序的对象锁，不反向升级。清单回收在事务内解除对象关系，只有对象无清单关系、无仍有效的工作 pin 且满足保留窗口，才可转 deleting；不能因 M1 被裁剪而删除仍被 M2 使用的原图。

历史媒体绑定有稳定 bindingId，记录来源内容修订/字段、媒体资源身份和具体清单。content 提供从来源修订解析该绑定的读取入口：复查来源修订可读、字段可读、绑定确实属于来源及目标媒体当前的读取/下载策略，然后定位固定清单。该路径不依赖媒体旧修订仍在历史列表；源绑定存续就保留清单及必要媒体资源身份。替换为 M2 或裁剪媒体旧修订后，合法来源绑定仍能读取 M1；不能回退当前清单，也不能公开裸 manifestId 下载。

文件夹关联的是可授权的集合文档，不是对象存储路径。文件夹与集合适用范围、父子防环、同级重名、非空删除及并发移动由 content 维护；移动不重写对象键。assets 的引用摘要只持有资源/集合身份，由 content 授权后补充可公开元数据。

HTTP 的上传/下载/资源管理调用 content 的统一公开用例，由它校验集合和文档权限并消费 assets 的窄能力。删除或更换媒体文档不能绕过相同的文档用例直接改 assets 表。物理资产 ID、存储回执或长期对象 URL 不能成为独立的权限旁路。

上传流程：

1. 校验集合配置、主体权限、配额和替换目标 revision，创建有期限及用途的上传会话。
2. 使用受限流式传输；如所选存储支持直传，凭据仅限本次会话的隔离暂存键、长度、期限和用途。客户端不能写最终对象，完成通知不是可信的文件验证结果。
3. 服务端从固定对象版本或条件保护的源取得字节，核验实际类型、大小和摘要，复制至服务端私有且不可复用的最终键，或固定不可变对象版本；再次确认最终字节。不得绑定仍可被原上传 URL 覆盖的对象。执行图片检查和必要处理，会话进入 processing、ready 或可观察 failed 状态；无法冻结源的提供方使用受控服务端上传。
4. 创建或替换媒体文档时，在同一 SQL 事务重新授权、检查 revision、锁定 ready 清单、消费会话并登记引用、审计和幂等结果。
5. 外部传输和图片处理不持有业务事务或授权锁；取消、超时、崩溃和未消费会话由持久化任务回收。

批量上传以多个可追踪会话及逐项结果实现；配置的数量、总字节与处理并发是容量限制，不是删除批量功能。续传/分片依赖所选存储能力，能力必须明确声明并测试，不向客户端返回虚假的成功。

派生任务按领取代次生成独立暂存/候选对象键，通过 owner/代次 CAS 才能绑定新清单；迟到任务不能覆盖已经发布的对象。CAS 失败或进程中断后的未绑定对象有持久化回收依据，存储 URL 的有效期不作为字节不可变保证。

取消/到期首先禁止消费会话及签发新凭据，保留会话/上传代次、已签凭据最晚期限、对象前缀和分片身份的持久化回收账本。已经签发的 URL 或已经开始的 PUT/分片可能迟到完成；删除一次暂存对象后不能立即将回收记为终态。适配器声明凭据及在途写入的可保证窗口，按提供方能力 abort 分片、复查并回收迟到对象；隔离暂存前缀配置生命周期及未完成分片清理作为兜底。无法证明不会再写入时保留可观察的核对责任，不把 URL 过期当作在途请求已停止。只有不会再产生写入且对象/分片均已回收才报告最终清理完成；重试耗尽保留失败账本并告警，不遗忘资源。

## 7. 版本、回收站、裁剪与恢复

集合支持下列明确模式。内部有效修订保持不可变；关闭历史仅改变历史保留/可见能力，仍保留运行所需的活跃修订，不无限积累不可查询记录。

| 操作 | 直接生效、无历史 | 直接生效、保留历史 | 草稿/发布、保留历史 |
| --- | --- | --- | --- |
| 普通保存 | 完整校验，生成新的当前生效修订 | 完整校验，新修订生效并保留历史 | 保存新草稿；发布操作完整校验并切换发布指针 |
| 自动保存 | 配置不适用，不能隐式当草稿保存 | 配置不适用，不能隐式当草稿保存 | 幂等保存新草稿，不修改发布指针 |
| 恢复历史 | 没有历史能力，配置/操作明确不适用 | 完整校验并生成新生效修订，同时要求恢复与直接生效写权限 | 按当前配置生成新草稿，不自动发布 |
| 恢复回收站 | 完整校验并要求生效写权限，恢复可读当前内容 | 同左，另保留恢复记录 | 恢复编辑可见性，发布指针保持空 |
| 定时发布 | 配置不适用 | 配置不适用 | 绑定确定的草稿修订，执行时重新授权 |

不适用组合在配置校验/操作契约中显式拒绝，不接受选项后无声忽略。版本比较经过字段授权；恢复读取历史字段和文件清单，按当前配置验证/显式迁移，不悄悄丢弃不兼容字段。恢复直接生效内容不能只凭草稿恢复权绕过生效写策略。定时发布执行时重新校验发起主体、权限、预期 revision 和目标状态；不得以 worker 超管身份绕过撤权。

回收站隐藏文档并取消发布；恢复按上述模式执行。永久清除使用独立权限、保留期限及外部引用检查；删除自身历史时同事务释放其引用，不能因为把自身版本也算作外部引用而使清除永远无法完成。

版本裁剪保护活跃草稿、已发布修订、待执行定时发布及保留策略要求的修订；先在事务内删历史/释放引用/登记清理意图，再异步删除不再被使用的对象。禁止仅按“最后 N 行”直接删对象。

入站内容关系默认限制目标删除，配置可声明当前关系解除或逻辑级联，并复查全部受影响资源权限与预算。解除为来源创建符合其模式的新修订，不修改保留历史或暗改已发布快照；逻辑级联归档/取消发布来源，仍保留其历史。任何保留历史、已发布修订及待执行任务的引用都继续阻止目标物理清除，直到来源按正常保留/清除策略合法释放。级联清除来源历史须独立、显式授权及清除计划，不能作为普通关系级联的隐藏副作用；引用锁与目标清除锁竞争同一内容资源行，避免检查后新建引用。

引用登记、替换、裁剪、清除及物理删除按第六节的清单/对象锁协议执行。保留版本、已发布内容及未结束的绑定工作仍需要的对象不能被清理。PITR 的对象保留窗口同样是清理条件；数据库回滚不能恢复已被永久删除的字节。

异步批量、文件重新处理和定时发布有持久化 jobId、collection scope、动作、发起主体、目标 revision、逐项结果及明确终态。受理返回 202 与状态读取位置；客户端重启后可继续查询。任务查询按当前动作/范围及来源资源权限投影结果，只对可读取项提供目标、错误和统计；发起身份及 jobId 本身不绕过撤权。排队/执行/成功/部分失败/失败/取消分别呈现，不能将受理或某个子项成功报告为全部完成。

## 8. 目录归属与验收路径

保留三个工作区及 identity/access/content/assets/audit 顶层边界。content 增加真实能力对应的 queries、uploads、folders、jobs；集合编译/字段规则归 collections/fields，SQL 映射编译归 adapters/postgres。database 新增物理计划生成能力与 schema/generated；生成命令归应用 commands。assets 按 uploads、manifests、processing、references、jobs 组织，随实现创建目录，不制造空壳。

资源查询与文件夹业务从属于内容引擎，存储工作从属于 assets；不存在独立的固定字段媒体 CRUD 与上传型集合 CRUD 两套实现。HTTP 路径和实施顺序见 [接口清单](modules-and-contracts.md) 与 [实施计划](implementation-plan.md)。

| 验收场景 | 必须验证的结果 |
| --- | --- |
| 定义两个集合及复合字段 | 同一份定义产生校验、可查询字段、类型和 schema；新增集合不修改通用文档用例 |
| 嵌套 array/blocks + 关系 + locale | 保存/查询/排序/展开/恢复保持类型、顺序和语言语义，目标权限与总数一致 |
| 复合唯一与历史 | 历史重复值不阻止合法当前写；两个并发当前写不能突破唯一约束 |
| schema 演进 | 重命名保数据、类型变更显式转换、旧修订可解码；配置/生成物/数据库不兼容时拒绝就绪 |
| 自定义媒体字段 | 上传型集合增加版权等字段，复用普通内容的校验、查询、权限和版本路径 |
| 文件替换与引用 | 发布内容和旧版本仍能取得原字节；新草稿使用新清单，未经授权不能读取任一版本 |
| 共享对象与历史定位 | M1/M2 共享原件时裁剪 M1 不删共享字节；媒体旧修订被裁剪后来源绑定仍可授权读取 M1 |
| 图片与取消 | 焦点/裁剪改变产生可追踪新变体；炸弹图、处理失败、断流及取消后迟到 PUT/分片不会留下失去回收责任的对象 |
| 回收站/恢复/裁剪/清除 | 草稿模式恢复不自动发布、直接生效模式验证写权、活跃修订受保护、引用释放准确、外部引用阻止清除 |
| 定时发布与撤权 | 发起后撤权、编辑冲突及重复领取均不会产生越权或重复发布 |
| 直接生效与异步结果 | 各配置模式下恢复可实际生效且不越权；重启客户端后可查询批量/处理终态和经授权的逐项结果 |
| 多实例及崩溃 | 领取代次/CAS、引用竞争、SQL/对象部分失败、备份恢复窗口均符合安全基线 |

这些是将来实现的验收要求。本轮只检查设计一致性、本地引用和格式；不记录任何 CMS 功能测试、压测或高可用演练为已通过。
