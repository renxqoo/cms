# 上传集合的文件控制

上传集合通过 `upload.filesRequiredOnCreate` 控制首次创建是否必须提交已处理文件，默认值为 `true`。草稿创建允许无文件。`false` 允许直接发布模式先保存资料、以后通过现有替换上传流程附加文件。该设置只约束新建，不追溯禁止已有无文件文档的编辑和历史恢复。无文件文档的下载和重命名返回 `not_found`，界面不显示文件预览或图像处理入口。

`documents.renameFile` 使用 `POST /v1/collections/:collection/documents/:id/file-renames`，输入为 `revision`、可选的单一 `locale` 和 `filename`，必须提供幂等键。服务端重新检查当前调用主体、委托凭据、集合更新和读取策略、编辑租约及修订 CAS。重命名复用普通保存的字段验证、钩子、引用验证、作者追踪、审计和版本清理流程。原扩展名必须保持，允许扩展名大小写变化；禁止空白名称、路径分隔符、控制字符、`.`、`..` 和未变化的名称。

文件清单不可变。重命名在同一安全事务内复制清单元数据并建立新的对象关联，不复制或改名存储对象。存储键是私有不透明 UUID，文件名只是下载元数据，不构成全局唯一命名空间；不同文档可以有相同显示文件名。历史修订、发布快照和其他文档已绑定的文件仍使用原清单。原图下载使用所选清单文件名，变体下载使用同一文件名主干、变体名和真实输出 MIME 的扩展名。

清理只回收没有修订引用及活动上传的到期清单；对象必须同时没有任何清单关联、任务保护及活动上传才可回收。重命名锁定来源清单，保证清理无法在克隆过程中撤走其关联。新清单与关联写入和文档修订提交原子完成，失败和取消全部回滚，不产生孤立清单。无需物理数据库迁移。

后台在可写且存在文件时提供重命名弹窗；请求携带当前逻辑语言与编辑会话，保留同一幂等键供网络结果不明时核实，冲突要求刷新。弹窗关闭和组件卸载取消请求并释放导航保护。

观测使用现有操作审计中的 `fileRenamed` 修订、版本号、HTTP 错误码和文件清理台账，不记录私有存储键。回滚配置仅影响之后的新建；已有无文件文档仍可维护。回滚代码前应先停用重命名入口，已生成的清单与普通清单完全同构，无需数据降级或双轨兼容窗口。

私有文件预览和下载链接采用下载响应中的真实文件名，包括变体的实际扩展名。资源缩略图只请求图像对象；文件清单改变时，选项从当前清单重新派生，已移除的变体回退到原件。切换、权限撤销和卸载都会取消请求并回收 Blob URL。
