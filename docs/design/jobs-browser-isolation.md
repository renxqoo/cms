# 工作发现浏览器旅程隔离

计划发布、上传会话、普通管理员访问拒绝和资源清理重试是四个独立旅程，不共享测试数据依赖。每个旅程使用独立 spec，沿用 browserGroups 为该 spec 创建的开发和生产应用、CMS、临时数据库与运行时角色。开发和生产仍各执行一次原旅程，保留全部业务断言。

原四个旅程放在同一个 spec 时，共享同一 CMS 的 60 秒 IP 限流窗口。独立实测开发模式初始化消耗 7 次 HTTP，按每个用例开始到下个用例开始分段，包含前用例的尾响应，分别记录 46、33、17、18 次，累计 121 次，超过生产 IP120/分钟；生产模式累计 115 次。最高每用户每操作计数为 39，未达到 60。仅运行最后的清理重试旅程时，开发和生产分别累计 25、26 次 HTTP，均通过。因此问题来自独立测试之间的窗口累积，不能归为单个业务旅程的异常轮询。

请求统计包括真实 CMS HTTP 日志中的 SSR 身份读取、操作目录分页、导航与业务请求；已取消请求若到达 admission，也消耗 IP 窗口。列表轮询为 10 秒、详情轮询为 5 秒，且终态停止，本次短旅程未形成高速轮询。原完整文件复现 7/8，通过隔离启动点单独执行清理旅程为 2/2。

隔离保留原生产限流、超时、轮询策略和所有浏览器断言。测试不清理限流桶、不伪造身份或 IP、不添加控制端点或数据库凭据通道。默认 test 脚本显式包含四个 spec，contentFeatures 对四个文件继续启用真实内容装置；分组回归确认每个 spec 有独立 world 生命周期。

验证范围为四个 spec 的全部 8 个开发/生产用例、既有分组与选择器单测、类型、lint 和构建检查。完整 CI 仍由仓库门禁运行，局部旅程通过不代表全仓通过。
