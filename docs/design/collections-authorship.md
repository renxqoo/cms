# Collections 作者追踪

状态：当前实施契约，2026-10-27。参考本地 Payload 的 authorship 自动归属语义，身份保持独立 admins 架构。

集合 authorship 缺省或 true 同时启用 createdBy 与 updatedBy，false 关闭两项，对象可分别关闭，缺项仍启用。createdBy 只记录创建主体；updatedBy 记录实际成功内容写入主体，包括保存、自动保存、发布、撤回、归档、恢复、批量与后台写入。复制记录复制主体，不能携带来源作者。身份列不进入可写 data，客户端和配置不能用同名字段覆盖系统归属。

0022_content_authorship.sql 新增可空 created_by、updated_by 外键，账号清除置空。旧记录只在修订一仍可验证时回填创建者，不从经过裁剪的最早剩余修订推测；当前修订仍存在时可回填更新者。回滚先停写并切回匹配配置与产物，保留列与历史审计；不把新增作者列转为普通可写字段。

作者显示通过 access 的公开参与者在同一事务中复核当前 admins.get 权限和原委托身份，再读取独立身份记录。应用装配将 access.readAuthor 注入 ContentOptions.resolveAuthor；未装配读取参与者时保留隐私，作者投影为 null。无权读取、未知或已删除统一返回 null，不泄露 email、凭据、角色或其他身份字段。详情、列表、关系展开与资源投影共用安全作者投影和请求内缓存。后台界面显示真实只读作者信息。

createdBy、updatedBy 支持 eq、ne、in、notIn、exists 元数据条件，eq/ne 的值为 UUID 或空值，in/notIn 为非空 UUID 列表，exists 为布尔值；必须启用相应开关并拥有 admins.get 权限，否则服务端拒绝且元数据不列为可查询。禁止身份字段 dot-path 穿透。服务端受信任集合策略可用已启用的作者 UUID 限制文档范围。操作仍遵守原安全锁、内容写 fence、修订 CAS、幂等、取消和 SQL 预算。

部署停写后先迁移再启动新实例，不同时混跑会遗漏归属的旧写路径。观测未知历史作者、授权失败、写入回滚及作者筛选拒绝；验证覆盖不可伪造、创建者稳定、复制重新归属、语言与后台动作、ACL/委托撤销、旧历史裁剪、查询边界和真实界面。

历史版本详情的 updatedBy 来自所选修订的 actorId，身份资料仍按当前主体的 admins.get 权限读取；恢复旧修订产生新的当前版本并记录恢复执行者。关系展开和关系查询的目标集合分别执行其作者开关与真实身份读取授权，源集合关闭作者追踪不会关闭已授权目标集合的作者展示。
