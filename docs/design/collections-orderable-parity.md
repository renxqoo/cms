# Collections 自定义排序

CollectionDefinition.orderable 启用自定义排序，关闭时拒绝排序管理操作和 `_order` 排序。启用后默认按 `_order` 升序；显式 defaultSort 与用户选择仍可覆盖，near 保持其专用平面距离排序。普通筛选、分页、语言和 rows/total 权限继续使用同一 SQL 查询。排序不修改正文或发布版本。

0019_document_order.sql 增加 content_order_control 与 content_document_order。控制记录以集合稳定 ID 为键，使用不可推断计数的 UUID 版本令牌；文档记录使用精确 numeric 顺序。迁移先停旧写入者，在 content_documents 与 content_schema_control 写锁内按 created_at,id 初始化既有文档，并为所有已注册集合初始化控制记录。同一常驻处理函数由集合注册和文档新增/物理删除触发，作为唯一实现。空集合与含隐藏文档的集合均返回稳定 UUID，不暴露 null 或计数差异；GET 不执行写入。新增文档及副本原子追加末尾；归档保留位置，恢复保留位置，与 Payload 保留文档 `_order` 字段的行为一致。触发器使用调用者权限，不使用 SECURITY DEFINER，PUBLIC 无 EXECUTE。运行账号只授予两张表所需权限。

documents.order 读取当前令牌，要求当前语言 documents.list 权限；不返回隐藏文档、数量或排序键。documents.reorder 输入集合、当前内容语言、UUID 令牌、一个或多个文档 ID 与目标文档 before/after；移动 ID 唯一、有界且不得包含目标。每个移动文档同时满足 reorder 和 documents.update 行策略，目标满足 documents.list 行策略；禁止操作回收站。目标相邻位置由服务器在同一锁内读取，保持未展示文档的相对顺序，不向客户端暴露相邻 ID。精确中点使用乘以 0.5 保留十进制精度；多个移动文档按输入顺序排列。排序键以部署 maxOrderKeyBytes 限制资源，超出预算明确返回 capacity_exceeded。

任何新增、物理删除或重排使集合版本令牌变化；重排先锁定控制记录并验证令牌，全部写入和审计在同一事务提交。冲突返回 version_conflict，管理端保留服务端顺序并提示刷新，客户端不在失败后伪造成功。网络任务沿用现有取消与卸载清理。

管理端只在启用且当前使用 `_order` 排序、编辑模式、未在回收站时显示重排操作列，保留显式切换自定义排序的入口。拖动行的手柄到另一手柄完成移动；键盘用户可用向上/向下按钮。行移动后重新读取列表与令牌，完整文档列仍由现有表格呈现。

兼容窗口为停旧写入者至统一产物切换后恢复写入。迁移期间不允许旧产物继续接写；旧读取产物忽略新表。以迁移 readiness、触发器属性、精确运行权限、CAS 冲突率、排序失败和新增缺失顺序数确认切换；切换后保持单一常驻触发器，不提供业务层排序双写路径。回滚上一统一产物并保留两张表与触发器，不自动销毁顺序。配置关闭不删除数据；重新启用恢复既有顺序。

验证覆盖真实 PostgreSQL 追加、现有数据迁移、前后与批量移动、CAS 并发、隐藏目标与移动权限、审计失败回滚、归档/恢复/副本、过滤/total 与升降序。组件与浏览器验证键盘、拖动、刷新持久化和错误反馈。四门与覆盖率以实际统一日志为准。
