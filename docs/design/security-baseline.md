# Hono CMS 安全基线

状态：经设计审查的安全基线。以下为必须落实的目标和责任分配，不表示防护已经部署或测试通过。

## 1. 边界与推荐执行顺序

入口和应用共同防护，应用端口只向可信入口开放。TLS 终止、WAF 和跨实例负载均衡由部署入口承担；Hono 负责应用协议、安全会话、授权和业务完整性。

```text
可信入口：TLS、证书、WAF、全局/IP 粗限流、连接/报文限制
  ↓
Node HTTP：严格解析、Header/URL 限额、接收超时
  ↓
最小请求上下文：服务端 requestId、计时、结构化访问日志/指标包裹
  ↓
安全响应头、管理接口 no-store、统一错误映射
  ↓
可信代理与真实 IP 解析、IP 访问策略、进程入口过载保护
  ↓
IP/全局应用限流、Host/方法/Content-Type/长度预检查
  ↓
CORS；合法 OPTIONS 在上述基础防护后结束
  ↓
匹配真实操作、认证、构建 Actor 与权限快照
  ↓
用户/操作限流、资源并发准入、请求取消/执行期限
  ↓
接口权限校验、参数解析与校验、资源级与业务规则校验
  ↓
需要时执行幂等协调，事务内重新核验授权与版本
  ↓
用例、数据库事务与外部存储操作
  ↓
响应序列化或流式下载；释放资源并完成访问日志/指标
```

requestId 和访问日志在认证前建立，才能覆盖 400、401、403、413、429 和预检；认证后补充 Actor，客户端声明的用户或组织不能直接进入可信上下文。requestId 不是分布式 traceId：追踪上下文应按 traceparent 标准校验和传播，不能以客户端任意字符串作为可信审计身份。

JSON 与 multipart 使用不同路径。已声明长度的超大请求尽早拒绝；真正读取时仍执行字节计数。无 Content-Length 的上传应在鉴权和并发准入后流式读取，防止认证前缓冲文件。顺序需要通过集成测试验证，而非只检查中间件数组顺序。

## 2. 逐项责任与复用选择

| 能力 | 本阶段要求 | 实现边界及复用 |
| --- | --- | --- |
| TLS 终止、证书校验 | 生产必须 | 反向代理/入口；出站 HTTPS、PostgreSQL TLS、SMTP TLS 也验证服务端证书，不关闭校验 |
| WAF、DDoS 防护 | 生产入口责任 | 复用部署平台、CDN 或网关能力；Hono 参数校验不能充当 WAF |
| CORS | 必须明确配置 | 复用 hono/cors；精确来源、方法和请求头允许列表，不使用生产通配来源 |
| 安全响应头 | 必须 | 复用 hono/secure-headers，按 JSON API/下载配置；入口负责外部 HTTPS 与 HSTS 策略一致 |
| IP 黑白名单 | 必须支持配置 | 复用 hono/ip-restriction；IP 由可信连接与代理规则提供；配置启用时拒绝项优先 |
| requestId | 必须 | 复用 hono/request-id，服务端生成；关闭默认接收任意客户端 X-Request-Id 的行为 |
| 请求上下文 | 必须 | 优先使用 Hono c.set/c.get；跨调用确有需要才使用 hono/context-storage，生命周期限定单请求 |
| 全局/IP/用户限流 | 必须 | Hono 官方内置中间件列表未提供完整分布式限流器；评估维护中的限流库及共享存储能力，不冒称官方内置 |
| Header/URL/请求体限制 | 必须 | Node HTTP 解析器限额 + 路由 Content-Type 策略 + hono/body-limit；multipart 补流式计数和分段数量限制 |
| Token 认证 | 必须 | 复用 hono/bearer-auth 的处理入口；会话校验、过期、吊销、账户状态属于 identity 用例 |
| JWT / OAuth2 / OIDC | 按接入需求 | 第一阶段建议不透明会话 Token；如采用 JWT 使用官方 JWT/JWK 能力并验证算法、签发方、受众与过期；OAuth2 接入另有完整流程 |
| RBAC 与资源级校验 | 必须 | access 模块，默认拒绝；列表、详情、版本、关系、下载和写入执行相同边界 |
| 参数校验 | 必须 | 路由 Zod 契约与 Hono 官方验证入口组合；业务规则不能只放在参数中间件 |
| 幂等、防重复消费 | 高风险写入必须 | PostgreSQL 原子幂等记录；邀请/重置令牌原子单次消费；版本控制与幂等职责分开 |
| 超时与取消 | 必须 | 复用官方能力时核实语义；hono/timeout 不等于自动取消数据库、邮件或文件写入，流式传输需单独管理 |
| 并发与资源隔离 | 必须 | 请求数、上传数、密码计算、数据库连接池均有上限，队列有限且可取消；与 RPS 限流不同 |
| 统一错误 | 必须 | Hono onError/notFound + 明确错误目录；不泄漏 SQL、堆栈、路径、令牌或 SMTP/数据库连接串 |
| 日志、审计、指标 | 必须 | 结构化日志适配；安全审计跟业务事务提交，访问日志覆盖所有退出路径，指标标签限制基数 |
| 缓存 | 管理接口禁止共享缓存 | 管理响应 no-store，先鉴权再读取；未来公开已发布内容另行定义缓存键和失效策略 |
| 灰度、负载均衡 | 入口责任 | 部署网关/平台；CMS Hono 服务接收已路由请求，业务内部不复制路由实例选择功能 |
| 熔断、协议转换、请求转发 | 有真实外部调用才应用 | 出站邮件/存储适配器有超时、并发和失败处理；第一阶段不把 CMS 建成通用代理网关 |

官方 logger 可作开发输出参考；生产访问日志需要结构化字段和脱敏，不默认把原始 URL、查询串或整个 Header 对象交给 logger。

## 3. 可信代理和请求边界

- 以 Node 连接地址为信任起点，只在直接对端属于已配置可信代理网段时解析 Forwarded/X-Forwarded-For。
- 入口清理客户端伪造的转发头；应用按固定信任策略从右向左解析，拒绝非法、多义或过长的转发链。不能直接取 X-Forwarded-For 第一项。
- IP 策略、限流和审计使用同一个规范化结果；涵盖 IPv4、IPv6 和 IPv4-mapped IPv6。
- 生产校验允许的 Host；应用自己生成的邮件链接从受校验的配置基地址构造，不信任 Host/X-Forwarded-Host。
- 限制 Header 总字节数、数量、URL 长度、接收 Header/Body 的耗时。保持 Node 严格 HTTP 解析，不通过宽松选项兼容畸形请求。
- JSON、multipart 和二进制分别允许 Content-Type；不支持的请求编码返回 415，不在应用内无上限解压请求。
- 查询参数限制长度、数量和重复键；排序字段和过滤操作符有允许列表，SQL 使用参数化查询。

## 4. 会话、授权与高风险操作

- API 不通过 URL 传递令牌；邀请/重置邮件链接仅在前端地址的 fragment 携带，兑换时置于请求体，日志不记录。数据库只存会话/邀请/重置令牌摘要，不保存可恢复密文或邮件正文。密码采用经过验证的 Node 兼容密码哈希实现及显式参数，禁止自行发明加密协议。
- 登录防爆破同时考虑 IP 和账户维度；未知账户不暴露是否存在，错误响应一致，不将任意 Token 文本作为限流键。
- 限流状态需要跨实例一致；单机内存计数不能宣称是集群限流。入口粗限流保护应用和计数存储不先被打满。
- 注销、改密、禁用账户、禁用角色和撤回授权有明确生效时序。权限不能长期固化进 Token。
- 鉴权绑定使用真实 operationId；未知操作、缺失绑定、无效权限默认拒绝。公开/仅认证名单按精确操作声明，不使用宽泛 URL 前缀放行。
- 动态集合接口按 operationId + 已注册集合范围查绑定；权限身份与绑定范围必须一致，禁止 global 兜底。文章、页面、历史版本和跨集合关系均纳入范围矩阵。
- 角色授权、超级管理员分配、权限创建/启停、接口重绑均防提权；权限code与scope创建后不可变，高风险配置默认仅超管维护。
- 请求体中的 ownerId、roleId、createdBy、publishedAt 等不能通过批量字段赋值绕过规则；DTO 使用严格字段集。
- 单组织是第一阶段范围，不接收可伪造的 tenantId。未来多租户必须同时改查询、唯一索引、缓存键、幂等和文件命名空间后才可宣称隔离。
- 当前 API 只接受显式 Bearer，不接受浏览器自动携带 Cookie 的认证。后续接入 Cookie/BFF 时，在相关边界落实 CSRF、Origin 校验及 Secure/HttpOnly/SameSite；CORS 本身不承担认证或 CSRF 全部职责。

## 5. 幂等、重放和超时

- 对创建管理员、发布、版本恢复、文件确认/删除等确定的变更操作定义幂等契约；不为所有 GET 或登录统一缓存响应。
- 幂等键按 Actor + operationId + 资源范围隔离，关联规范化请求指纹；同键不同请求返回冲突。
- 重试先重新认证授权，再读取结果；撤权后不能通过旧幂等键读取敏感响应。响应记录不得保存密码、会话或重置令牌。
- 数据库业务写入、审计与完成态幂等记录在同一事务提交。并发首请求唯一，进行中和崩溃后的行为明确可测；文件/SMTP 副作用按模块状态机处理，不能假定与 SQL 原子提交。
- SQL 操作在业务事务内用唯一键争取幂等记录，不提前提交一个永久 processing 状态。同键竞争有限等待；超出期限返回可重试冲突。事务回滚则记录一并回滚，提交则保存脱敏结果引用和指纹，响应在提交后发出；TTL 后删除代表去重窗口结束，文档明确窗口。进程在提交后响应前崩溃，重试重新鉴权后读取完成结果。
- 外部工作意图与 SQL 同提交，由所属模块维护执行状态；不能在一个 SQL 事务中等待对象上传或 SMTP。身份邮件按用户裁决严格只存令牌摘要，提交后有界内存执行器只尝试一次，不自动重投；失败/崩溃标记 failed/unknown，由用户显式重新发起并作废旧令牌。公开重置申请不等待 SMTP，统一返回受理结果。认证令牌响应不进入幂等结果缓存，详见[身份专项设计](user-rbac-design.md)。
- 幂等只能解决业务重复执行；Bearer Token 被盗后的重复使用需要令牌保护、过期、撤销和高风险再验证。未来 Webhook 才按其提供方协议实现签名、时间窗和 nonce 去重。
- 请求期限传播到存储和下游；PostgreSQL 同时配置 statement_timeout、lock_timeout 和连接获取期限。
- 超时返回不代表事务一定未提交；发生提交边界不确定时，应以幂等状态查询和重试恢复，不能自动再次执行写操作。
- 上传、下载和客户端断开触发流中断、句柄关闭及临时文件处理。信号量必须在 finally 释放。

## 6. 文件与内容安全

- 上传需要鉴权、限流和准入后才消耗文件解析资源；限制文件数、字段数、单字段长度、总字节数和单文件字节数。
- 不信任客户端 MIME 和扩展名；检测实际类型，拒绝未批准的 HTML、SVG 和可执行内容。PDF/Office 默认附件下载，不承诺文件无恶意内容。
- 存储键由服务端生成；校验目标路径不越出存储根目录，处理符号链接和并发路径替换风险。
- 原文件、缩略图、版本和下载链接不能绕过权限；不将私有文件以静态目录或永久公共 URL 暴露。
- 媒体采用上传型集合，字段读写、筛选/排序、总数、关系展开、历史、原件/派生图均执行所属集合及文档权限；物理资产 ID 和上传回执不能代替授权。
- 上传会话绑定主体、collection scope、用途、期限和替换目标 revision；消费时重新授权。直传凭据只可写隔离暂存对象，最终绑定使用不可被客户端覆盖的已验证字节版本或服务端私有对象。不能在校验后继续绑定可能被同一上传 URL 改写的键。
- 取消/到期禁止消费和新凭据，但不假定旧 URL 或在途传输立即失效。上传代次、暂存键、凭据期限和分片身份保留持久化回收责任；迟到写入再次清理，隔离前缀生命周期/未完成分片清理兜底，不能删除一次就忘记会话。
- 图片解码及派生处理限制像素、帧数、尺寸、内存、CPU、输出字节和并发；校验元数据、处理配方及支持格式。处理在业务事务外执行，失败/取消/旧任务完成不能覆盖新清单。
- 生产采用跨实例共享私有对象存储；内容→清单及清单/工作→对象两层引用分别竞争所属清单/对象行锁，锁后复查状态和保留窗口。共享原件/派生对象在所有使用者释放前不可删。来源修订固定的媒体绑定校验来源、字段及目标权限，不能通过裸清单身份绕过授权。数据库恢复窗口与对象版本及删除保留窗口协调。
- 富文本使用受限结构；字段长度、深度、节点数、链接协议和引用均验证。禁止执行 HTML、脚本、任意 SQL 或模板表达式。
- 查询 AST 限制路径、节点、关系深度、返回字节和 SQL 数量；字段权限也作用于过滤/排序/搜索，防止用总数或排序泄漏隐藏值。SQL 值参数化，标识符只来自已验证的生成映射。
- 受信任的字段/集合扩展点不能关闭授权、事务及审计；网络效果登记为提交后持久化工作。定时发布执行时重新校验发起主体，不使用 worker 身份绕过撤权。
- schema 生成不执行在请求中；构建产物与迁移兼容验证失败不 ready。版本裁剪和永久清除遵守外部引用、活跃修订及对象/PITR 保留窗口。
- 第一阶段不提供任意 URL 抓取/导入接口；将来添加时单独防 SSRF、内网访问和重定向绕过。

## 7. 日志、失败和生命周期

- 访问日志：requestId、operationId、状态码、耗时、规范化来源、必要的 Actor ID；URL 只记录规范化路径，不记录含令牌查询串。
- 审计：操作者、操作、目标、脱敏变更摘要、结果与 requestId；成功业务变更与审计同事务，拒绝事件另作安全日志。
- 禁止记录 Authorization、Cookie、密码、邀请令牌、重置令牌、数据库连接串和上传正文。
- 指标只使用受限标签，不将用户 ID、文档 ID、IP、原始路径或 requestId 作为指标标签。
- 鉴权或共享限流存储不可用时，管理接口默认拒绝并返回 503，不降级为放行。
- 优雅退出先摘除就绪状态，再停止接入、等待有限时间、取消剩余任务、关闭连接池与文件句柄。定时器、监听器和信号处理器可回收。
- 摘除就绪后先停止领取任务，等待入口摘流再停止接入；数据库池最后关闭。所有实例共用授权锁协议，安全写、幂等读取和即时授权只读 writer。全局连接预算包含滚动发布额外实例。

## 8. 初始预算提案

以下是待压测校准的初始配置提案，不是已验证容量；配置层集中定义并注入，不能散落在底层函数中。

| 项目 | 初始提案 |
| --- | --- |
| Header 总量 / URL | 16 KiB / 4 KiB |
| JSON 请求体 / 列表页大小 | 1 MiB / 最大 100 条 |
| 单上传会话 | 一个文件，起点最大 20 MiB，另限制 multipart 开销；批量由有界多会话实现，不删除批量能力 |
| 普通处理期限 / SQL 语句期限 | 15 秒 / 5 秒 |
| 单实例上传并发 / 密码计算并发 | 4 / 4；等待队列有界 |
| 普通 IP / 用户操作限流 | 起点分别 120 次/分钟、60 次/分钟；登录、邀请、上传另设更严策略 |
| 幂等记录保留 | 24 小时；邀请/重置有效期独立定义 |

## 9. 强制验收

Vitest 单测、真实 PostgreSQL 的 HTTP 集成测试与真实 Node 产物旅程共同覆盖：

1. 伪造转发头、IPv6 等价形式、非法 Origin/Host、超长 Header、超大及分块请求。
2. 预检无业务副作用；进入 Hono 的 400/401/403/413/429/500 均有安全响应头、requestId 和脱敏日志。Node 解析前拒绝由 bootstrap 的 clientError/服务器限额处理：连接级 ID、最小安全错误与日志，不声称这些请求经过 Hono 或拥有同一请求上下文。
3. 过期/撤销会话、角色撤权、缺失绑定、静态/动态路由冲突、HEAD 授权、跨集合及版本/文件越权读取。
4. 并发授权更新、最后超管保护、发布权限、历史版本和文件引用绕过。
5. 多应用实例限流、计数存储故障、有限队列、并发准入及取消后的容量恢复。
6. 同键不同请求、并发重试、撤权后重放、事务提交边界不确定、单次令牌并发消费。
7. 文件伪造类型、穿越/符号链接、传输中断、SQL/文件部分失败和清理任务回收。
8. Bun 开发与 Node 生产运行差异；不得把只在 Bun 下通过的测试当作 Node 兼容证明。
9. 自定义媒体字段、替换后历史字节、裁剪/焦点与派生处理预算、上传回执伪造、校验后覆盖、旧处理器迟到及批量部分失败。
10. 本地化及字段权限下过滤/排序/总数侧信道、关系循环、schema 迁移/历史恢复、裁剪及定时发布的撤权与竞争。
