# Collections 字段与呈现契约

状态：实施中。按本地 Payload Collections 能力补齐，保留既有严格数据、权限、查询预算和组件体系。

文本与数字字段支持有序 hasMany 值及 minRows/maxRows，元素使用同一标量约束，允许重复原始值；关系及选择字段继续要求唯一成员。日期字段保持单值。radio 使用单选字符串值。select/radio 的选项可以是字符串或带 value 与 label 的对象；label 可按界面语言配置，持久化、过滤、唯一性和生成类型只使用 value，标签变化不要求迁移数据。后台多值控件可增加、移除、移动和键盘编辑，错误参与现有表单保存门禁。

字段条件根据当前根数据、同级数据、路径和当前用户重新计算，并控制后台呈现、required 和自定义业务校验；结构、已填写值的基础类型约束和字段读写策略始终执行。布局条件向后代传递，同级数组条件按稳定行 ID 计算。静态提交 schema 和生成类型将可能受条件影响的字段标为可选，最终是否必填由服务端候选数据确定。自定义组件通过受信任的应用注册表装配，配置只传稳定组件标识，不把函数或任意模块路径交给浏览器执行。

关系候选过滤在服务端结合源文档、候选数据、字段约束和目标读取权限执行，保存时再次验证。候选分页与 total 必须在完整过滤后产生。字段展开深度和集合默认展开投影仍受请求及全局展开预算约束，不绕过目标权限。

本轮所有 HTTP/DTO、生成类型、架构检查和测试随实际实现同步，不保留旧路径别名；尚未实现的配置不会标为完成。

关系与上传字段的 maxDepth 是从顶层文档计数的绝对展开上限，可设为零以保留标识。相同目标经不同字段访问时分别遵守各字段深度，不能复用更深的结果绕过限制。目标集合的 defaultPopulate 只选择展开后的 data 字段，不改变顶层显式 select；未选字段及其 join 不会因后续展开重新出现。两项均为读侧行为，不改变已存储字段值。

候选端点为 `POST /v1/collections/:collection/editor/options`。输入包含 `candidate`、稳定字段 `path`、目标 `relationTo`、搜索与分页。候选提供当前表单数据；编辑、自动保存和复制绑定文档 id/revision，创建可使用原编辑描述的签名 initialSnapshot。服务器重新核对源操作、源字段可读写范围和目标读取权限，不能用候选端点覆盖只读值、改变源集合或绕过版本冲突。filterOptions 为静态 Where 或具有 version 的异步函数，函数只接收不可变且按字段读取策略投影的根数据、同级/块数据及路径、语言、主体和取消信号；布尔 false 产生空候选。列表与 total 在同一个 SQL 谓词下执行，函数调用、SQL、正文和响应均沿用现有预算。

保存、自动保存、复制、历史恢复和发布在事务中以最终数据重新验证关系候选约束；目标后来不再符合条件时，已有选项不能靠旧浏览器缓存或直接请求继续写入。失败回滚修订、指针和引用，不产生假成功。普通引用和未配置过滤的富文本引用继续使用现有授权列表接口。

批量编辑的 candidate 使用同一字段的数组形态，数组按同步批量预算限长。服务端在同一安全事务内核对每份源文档的当前修订与读取/更新权限，把每份候选条件取交集后执行一次目标查询与 total。批量表单仅发送当前补丁，旧值在服务端逐文档读取并合并；不能在浏览器对各自分页结果取交集，不能借用任一源的权限代替其余源。collectionSpecific 标签自动使用同一候选通道，空适用集合表示不限；选择器和最终写入都遵守标签适用集合约束。
