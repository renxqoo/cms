## 第一轮：功能与安全边界

只读审计 Tillgate，并用三个最小探针确认接口匹配依赖行顺序、分组层级及自定义页面校验缺口，证据见 [参考审计](reference-audit.md)。独立安全审查提出动态集合 scope、撤权时序、资产删除与引用竞争、幂等崩溃及 Node 解析前失败等问题。

处置：权限身份与菜单分离；绑定依赖真实操作及显式范围；用例内重新授权；共享/独占事务安全锁约束写入次序；资产行 FOR UPDATE 保护状态/引用；SQL 变更、审计、幂等同事务，外部效果使用恢复状态。Node 解析前拒绝与 Hono 错误分别验收。

## 第二轮：可维护性与备选结构

独立审查比较单应用垂直模块、三个工作区及逐域拆包。发现 operations 职责混合、操作 ID 来源冲突、集中 schema 缺 owner、共享事务责任不清及公共导出未限定。

处置：保留三个 private 工作区；移除 operations，文件恢复归 assets；只保留职责明确的平台能力。业务拥有操作身份，HTTP 引用；补充表所有权、跨域投影、事务最外层开关及小公共入口。不引入通用 UoW/DI/workflow 框架。源码及取舍见 [研究证据](research-evidence.md)。

处置：生产共享对象存储、writer 授权读、明确同步提交与 RPO 0 的可用性代价、领取代次/CAS、外部至少一次语义、集群连接预算、发布兼容窗口、停止领取和摘流排空顺序。SLO/RPO/RTO 保留为需演练的提案，不写成已达标。
