# OneAster 全新内容系统设计基线

状态：定稿，用户已于2026-10-27确认实施。级别：大。

关联：[接口与数据单元](CONTRACTS.md)、[实施及验收](IMPLEMENTATION.md)。本次使用 feature-dev-v2；借用跨应用功能的设计、施工、单元三件套，不实施旧 CMS 数据迁移。

## 1. 用户裁决与范围

- 用户裁决：new-cms 成为 OneAster 唯一 CMS；客户端替换全部旧 CMS 接口；从零录入内容，没有旧内容数据需要迁移，不保留旧接口兼容层。
- 用户裁决：模型列表、详情、展示标题、手填业务 `modelId`；业务 key 与 Core 定义一致。CMS 内部文档 ID、业务 key、页面 slug 分离。
- 用户裁决：每个模型单一主要分类，输入、输出类型和能力独立配置；统一展示各调用方式及语言示例，复用公共模板。
- 用户裁决：保留模型详情现有在线试用；不同类型使用各自真实业务链路。参数编辑、资料样例、历史、收藏及已有导航交互不能因内容源切换而丢失。
- 用户裁决：方案全部确认后开始实现；多子 agent 并行开发，worktree 物理隔离；交付生产可用代码与高可用验证证据。
- 既有仓库约束：首页视觉、布局、响应式、动画与交互保留；Core 继续拥有认证、密钥、余额、计费、用量和真实执行。

## 2. 需要确认的方向

1. 建议第五主类使用 `audio`，语音合成作为具体任务；其他主类为 `text/image/video/embedding`。
2. 建议新公开协议按页面聚合边界保证一致性，替代旧全局 snapshot 协议；详情正文与 metadata 共用同一请求内 reader，sitemap 使用单次一致的导出流。
3. 用户裁决：本次仅实现 CMS 与 client，不扩展 Core；保留文本、图像、视频真实试用。向量、音频可以管理和展示，调用入口仅在业务端实际支持后启用。当前 Core 0.18.1 的 Messages、Responses、向量、语音没有公开处理器，不注册假适配。
4. 建议延续已存在的同语言内置界面译文容灾；模型、文档、首页内容、报价和执行结果没有本地补造。
5. 高可用交付包含代码、双实例故障旅程、容量数据、部署与恢复手册。线上部署及故障演练属于独立发布操作，需在环境准备好后单独授权。

## 3. 内容所有权与模型身份

`models` 是统一集合，不按开发商或模态拆集合。`modelId` 非本地化，数据库唯一性同时覆盖当前草稿、仍发布的版本及回收站当前值；保留历史不永久占用旧 key。标题、简介、正文、SEO 按语言维护，技术身份跨语言共用。模型采用整文档原子发布，不使用按语言分叉的技术身份。

模型的 `contentLocales` 明确选择该 revision 对外提供的语言，至少一种。发布只对所选语言完整校验，不要求所有站点启用语言都有翻译；不以 fallback 补造翻译。新增语言不会自动进入已有模型的 contentLocales。未选语言的部分草稿可保存，但公开投影禁止输出。管理端在整文档发布前展示所有语言及技术字段的变化；一次发布切换同一模型的全部公开语言，不能只在某语言更换 key。此策略作为 content 的原生可配置发布校验能力实现，不能仅把现 localizeStatus 设为 false 后沿用遍历全部 supported 的校验。

管理员可更正 `modelId`：保存草稿期间公开页面继续使用已发布 key，发布时切换。UI 明确显示身份变更，统一生成的代码与试用入口随同一公开投影更新。更改 CMS key 不修改 Core 配置。Core key 不存在、无权限和不可用分别依据业务接口反馈，不能把静态资料当执行授权。

同一 key 的不同参数模式作为调用场景；不同业务 key 使用不同模型记录，可归同一 family。外部提供商的上游 key、路由优先级和凭据归 Core，不进入 CMS。

## 4. 数据与管理界面

实际业务集合包括开发商、模型、文档、站点设置、首页、语言配置与 UI 消息；复用已有媒体集合和通用内容引擎。集合按字段、组、数组、blocks、关系组织，不能以整页无约束 JSON 替代可维护表单。

模型分为基本信息、技术规格、调用方式、详情资料、展示样例、发布与 SEO。`technicalCapabilities` 记录有来源的模型技术声明，包含输入、输出、任务和能力；`apiBindings` 记录本站实际开放的调用范围。两者具有不同语义，不能把厂商声明当作平台支持。卡片展示技术声明，明确标识平台实际可调用状态；接入和真实试用只消费 binding 与 Core 实时能力交集。目录的普通技术筛选读取 technicalCapabilities，平台可调用组合筛选必须在同一 binding 内成立。

允许 apiBindings 为空且 defaultBindingKey 为 null，适用于本次可展示但尚无 Core 执行适配的向量、音频模型。此时保留规格、介绍、样例、参数说明和本地参数编辑，不展示可执行请求按钮或虚构平台代码。reasoning/coding 等任务单独建受控词表，不混入主要分类。

规格按文本、图像、视频、向量、音频能力组维护；多模态模型可有多个规格组。已能从参数合同推导的信息不重复录入。未知值用显式未知，不以零或编造默认值代替。

详情保留概览、接入使用、在线试用。接入使用按入口、调用方式、场景、语言切换，提供代码复制、接入说明复制和文档链接。只有已实现并有完整模板的组合可启用。

公共接口定义与生成代码属于受控技术配置，CMS 选择定义并维护样例输入及说明。模板不在 CMS 执行任意脚本；格式由语言 serializer/renderer 生成，不进行不受限字符串替换。

## 5. 公开交付与一致性

新接口位于 `/v1/public`，具体单元见 CONTRACTS。后台管理读写仍走已有鉴权接口，不能通过模拟管理员身份实现匿名公开读取。

受限公开读取归 `packages/cms/src/content/delivery`，SQL 归 content 的 postgres adapter；HTTP 仅接收装配后的业务 API。集合及公开字段白名单由部署配置注入，禁止请求者自由指定管理集合、编辑模式、字段投影或展开深度。

数据库新增明确的只读一致事务入口，使用 `REPEATABLE READ READ ONLY`。单次公开聚合响应的主体、关系、计数和分页元数据使用同一事务视图。首页包含推荐模型，目录包含匹配计数，详情包含相关资料与模型，文档入口包含目录和入口正文。

不承诺两个独立页面请求固定同一版本。站点 shell 与正文允许在各自完整聚合边界之间看到先后发布，语言及消息合同必须兼容，正文与 metadata 不分叉。独立的 Core 报价和用户权限始终是实时业务状态。

普通关系没有冻结目标 revision。公开投影只能读取已发布目标：未公开的可选开发商、相关模型和推荐项不输出；必需配置缺失明确失败，不能泄露草稿或借管理员权限补齐。媒体通过已公开内容 revision 的绑定读取，不能匿名开放管理端文件下载。

公开revision为语义data及依赖配置的规范化摘要，排除revision自身与请求时间等瞬时值；ETag再覆盖最终序列化DTO。不能用包含未发布修改的 document.updatedAt 充当公开版本。公共 JSON 默认 `public, max-age=0, must-revalidate`；预览、管理、错误响应均 `no-store`。条件请求、304、HEAD、Vary、CORS 一起定义。客户端没有对应完整 body 时不能处理成空的 304 成功。

## 6. 在线试用与 Core 边界

必须保留文本 Studio 的 Key 选择、输入、上下文、报价估算、会话、意图查询、部分文本、终态、历史及恢复；保留图像/视频 Media Studio 的参数、提交、lookup、任务状态、结果和历史。

现文本浏览器侧轮询 run/partialText，不能误改成假定浏览器直接消费上游 SSE。现资料参数编辑器只本地校验和复制请求映射，仍与真实执行结果分开。

试用选择依据明确的执行适配器和 Core 可用模型交集，不能仅根据主分类渲染通用提交按钮。流、轮询、任务、媒体消费各有清理；语言切换不得清空在途业务意图或错误地新建计费请求。

向量/语音及新协议是否本次扩展见第 2 节。未支持时公开说明当前状态，不伪造返回，不以供应商原生支持推断 OneAster 网关已经支持。

## 7. 多语言、文档和预览

沿用动态 BCP47 语言及 RTL 行为；去除补充模型资料固定语言联合与普通路由不一致的限制。原生内容引擎新增运行时 localeSource：在请求事务内从语言目录解析可编辑/可公开语言，不修改共享注册表；物理 locale 列继续使用 text，指纹记录 localeSource 合同身份，不因目录数据变化产生虚假物理迁移。写入、校验、查询、关系、发布、唯一保留、历史和编辑元数据都使用同一解析结果。禁用语言停止公开，保留已存数据、唯一保留与管理员历史访问；有内容引用的语言记录禁止直接删除。

模型按第 3 节整文档发布并选择实际完整语言；普通文档的翻译可独立发布。默认只返回请求语言确实完整且已公开的内容，不把不存在的翻译输出为语言关系。站点默认语言可以用于显式界面降级，但业务正文不静默跨语言回退。

interface 请求必须指定客户端 UI 消息合同版本。messageBundles 按 contractVersion、locale、namespace 唯一；已发布版本不可原地改义。常规滚动发布保留当前及紧邻前版合同，最长 24 小时，客户端配套就绪并排空旧进程后删除前版；不提供隐式字段双收或无限版本兼容。没有匹配完整版本返回 503；浏览器旧构建通过部署版本检测要求完整刷新，不把新合同硬塞旧页面。

文档保留富文本、提示框、步骤、代码、代码标签、接口、参数表、折叠、链接和媒体。新 CMS 公开富文本结构成为唯一标准，客户端 renderer 同步适配，移除旧 Lexical 公共格式契约。

模型草稿预览沿用必要的隐私行为，升级为新协议并完整预览模型草稿。采用 CMS 持久化短期随机 grant，仅保存摘要，绑定签发者、文档、语言、具体 revision、可信 client origin 和到期时间，最多 600 秒；签发及读取检查签发者当前身份与读权限，支持撤销。入口验证后 303 到无凭据地址，HttpOnly cookie，禁止缓存/索引/引用来源泄露，退出清理。凭据不进入日志、客户端 props、截图或 referrer。公开接口不接受 draft 参数。

草稿媒体通过 client 同源 BFF 读取：BFF 从 HttpOnly cookie 取得 grant，以服务端请求转交 CMS 专用 preview media 用例；CMS 校验 binding 确实属于该 grant 的文档 revision。不能把 client cookie 假定为 CMS 域凭据，也不能放开普通公共媒体路由。

首次启动使用显式、幂等的内容初始化命令导入随软件交付的语言定义和完整 UI 译文资源，初始启用 en/zh；它们是实际界面译文，不是旧 CMS 数据。命令只插入缺失记录，已有编辑不覆盖；合同不完整明确失败。模型、开发商、首页、文档均不自动填 demo。管理员录入并发布 site 后 shell 可用，再发布 home/documents/models；业务内容为空时显示真实空状态，必需配置未完成时显示初始化提示。CMS 完全不可用时仅已内置的同语言界面资源可降级，未知语言不借英文冒充；已收到的明确禁用状态不能被 fallback 覆盖。

## 8. 预算与生产验收目标

- 公开普通 JSON 页大小默认 20、最大 100；普通 DTO 最大 2 MiB；展开深度最大 3、节点最大 500、SQL 最大 200，沿用当前预算并按真实使用收紧。
- 客户端公开 JSON 请求总时限 5000 ms，CMS 公共只读用例时限目标 4000 ms，数据库语句上限沿用 5000 ms 且服从请求剩余预算；所有取消传播到事务和流。
- sitemap 与完整文档/模型指南索引使用一致读导出，按 CONTRACTS 第 4 节的 start/item/end 帧消费，必须校验完成标记、计数和摘要；不能把移除 snapshot 后的普通分页扫描当一致导出。单实例最多 1 个导出占用数据库连接，总时限 15000 ms、写空闲时限 2000 ms、客户端总时限 20000 ms，每批最多 100 条，最大 100000 条/32 MiB。期限覆盖最后一字节；取消、超限、消费者停读均释放事务及连接。普通请求的 4000/5000 ms 与 2 MiB 预算不用于导出流。
- 文档入口仅含入口正文和有界局部导航；完整文档/模型指南通过索引导出供独立可搜索分页组件消费，不能因文档正文或摘要总量变大而截断指南。client 对导出使用最大 128 MiB 的有界解析/索引预算，超限明确不可用，不输出部分 sitemap；超过单个 sitemap 的路径容量使用 Next 分片，每个分片按稳定路径哈希归属，每次分片读取自身完整一致导出，不使用会漂移的 offset 分片。
- 新增持久缓存必须有有界容量和失效规则；首期只在服务端支持 ETag，client 保持 no-store，不引入跨请求 body 缓存。ETag 不依赖进程内全局内容快照。发布后任意实例可读取相同公开事实。
- API 已有每实例最大 64 个请求、数据库池 10 个连接、退出期限 10000 ms；新增用例遵守准入，不创建无界队列。公开 SSR 消费者共享来源 IP 的限流单独配置，不能沿用管理员默认速率导致正常站点饥饿。
- 本地双 API 实例共用数据库及存储，验证发布、读、重启、停止一实例、超时、取消和资源恢复。性能验收记录数据量、RPS、p50/p95/p99、失败率、内存与连接，而不是只记录 200。
- 生产拓扑目标为至少两个 API 实例、共享持久存储、PostgreSQL writer 的备份及故障恢复能力、负载均衡与 readiness 摘流。月可用性目标、RTO/RPO 需要部署环境与持续监测证据，不能仅凭本地测试宣称线上达标。

## 9. 单轨切换与回滚

开发阶段可分批验证；交付时客户端仅保留 new-cms 内容源，新旧 CMS 不运行双读或旧路径回退。Core 链路保持其业务合同，除用户明确追加的后端扩展。

没有旧 CMS 业务数据迁移；新集合仍使用数据库有序迁移生成物，禁止修改已发布迁移。回滚使用本次前的配套代码版本和相应运行账号，保留兼容新增表，不自动删除新录入内容。API 与客户端以配套版本发布，内容准备及运行检查完成后切换；旧接口删除条件为所有生产调用、测试装置及真实服务验收均使用新协议。
